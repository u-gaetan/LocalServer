1À propos de cette extension

Cette extension Google Chrome a été développée dans le cadre du projet de recherche Validation de questions de connaissances générales pour l'étude des processus de recherche d'information Web, approuvé par le Comité d'éthique de la recherche en psychologie et en sciences de l'éducation (CÉRUL, dossier 2025-460 A-1 / 04-05-2026).

L'extension est un outil de mesure scientifique distribué exclusivement aux participants recrutés via un lien direct. Elle n'est pas répertoriée dans le Chrome Web Store et n'est pas destinée au grand public. L'infrastructure est hébergée sur Microsoft Azure (région Canada Est, Québec), fournisseur institutionnel approuvé par l'Université Laval.

2Données collectées

L'extension ne collecte aucune donnée avant que le participant n'ait cliqué sur « Commencer l'étude » après avoir donné son consentement éclairé. La collecte s'arrête automatiquement et définitivement à la fin du questionnaire.

L'extension ne collecte jamais : l'historique de navigation antérieur à l'étude, les mots de passe ou formulaires de connexion, les données financières, le contenu textuel saisi au clavier (seul le contenu copié-collé volontairement est enregistré), les données de géolocalisation, les communications privées.

3Finalité de la collecte

Les données sont collectées exclusivement à des fins de recherche scientifique sur les processus cognitifs impliqués dans la recherche d'information Web. Elles ne sont utilisées à aucune fin commerciale, publicitaire ou de profilage et ne sont jamais revendues à des tiers.

4Sécurité et chiffrement

L'infrastructure a été conçue en collaboration avec le Bureau du Numérique en Recherche (BNR) de l'Université Laval.

  • Transit : chiffrement TLS 1.3 entre l'extension et l'API Azure.
  • Repos : chiffrement AES-256 natif dans Azure Cosmos DB.
  • Chiffrement au niveau des champs sensibles (CSFLE) : les URLs complètes et le contenu du presse-papiers sont chiffrés à la source via Azure Key Vault, avant ingestion dans la base de données. Même les administrateurs Azure ne voient pas ces données en clair.
  • Épinglage de certificat : l'extension vérifie l'identité du serveur Azure pour prévenir les attaques MITM.
  • Contrôle d'accès : accès limité au chercheur principal et à l'étudiant-chercheur, protégé par MFA (SSO ULaval). Aucun secret en clair dans le code (Managed Identity Azure).
  • Pseudonymisation : chaque participant reçoit un code (ex. P042). La table de correspondance est conservée dans un fichier chiffré (AES-256) séparé, accessible uniquement au chercheur principal.
  • Journalisation : tous les accès, exports et suppressions sont consignés via Azure Diagnostic Logs.

5Partage des données

Les données brutes sensibles (URLs, contenu copié-collé, contenu textuel des pages) ne sont jamais partagées à l'extérieur de l'équipe de recherche autorisée. Seules des données anonymisées de façon irréversible pourront être partagées à des fins scientifiques non commerciales : métriques agrégées, scores au questionnaire, résultats d'analyse.

L'étude respecte la Loi 25 du Québec, le PIPEDA, l'EPTC 2 et la Politique des trois organismes (CRSNG).

1About this extension

This Google Chrome extension was developed for the research project Validation of General Knowledge Questions for the Study of Web Information-Seeking Processes, approved by the Research Ethics Committee in Psychology and Education Sciences (CÉRUL, file 2025-460 A-1 / 04-05-2026).

The extension is a scientific measurement tool distributed exclusively to recruited participants via a direct link. It is not listed in the Chrome Web Store and is not intended for the general public. Infrastructure is hosted on Microsoft Azure (Canada East, Québec), an institutional provider approved by Université Laval.

2Data collected

The extension collects no data before the participant clicks "Start the study" after giving informed consent. Collection stops automatically and permanently at the end of the questionnaire.

The extension never collects: prior browsing history, passwords or login forms, financial data, typed text content (only voluntarily copy-pasted content is recorded), geolocation data, or private communications.

3Purpose of collection

Data is collected exclusively for scientific research on cognitive processes involved in web-based information seeking. It is not used for any commercial, advertising, or profiling purpose and is never sold to third parties.

4Security and encryption

The infrastructure was designed in collaboration with the Bureau du Numérique en Recherche (BNR) of Université Laval.

  • In transit: TLS 1.3 encryption between the extension and the Azure API.
  • At rest: native AES-256 encryption in Azure Cosmos DB.
  • Client-Side Field Level Encryption (CSFLE): sensitive fields (full URLs and clipboard content) are encrypted at the source via Azure Key Vault before ingestion. Even Azure administrators cannot read these fields in plaintext.
  • Certificate pinning: the extension verifies the Azure server's identity to prevent MITM attacks.
  • Access control: limited to the principal investigator and research student, protected by MFA (ULaval SSO). No secrets stored in plaintext in the code (Azure Managed Identity).
  • Pseudonymisation: each participant receives a numeric code (e.g. P042). The linkage key is stored in a separate AES-256-encrypted file accessible only to the principal investigator.
  • Audit logging: all access, exports, and deletions are logged via Azure Cosmos DB Diagnostic Logs.

5Data sharing

Raw sensitive data (URLs, copy-pasted content, web page text) is never shared outside the authorised research team. Only irreversibly anonymised data may be shared for non-commercial scientific purposes: aggregated metrics, questionnaire scores, analysis results.

The study complies with Québec Law 25, PIPEDA, TCPS 2, and the Tri-Agency Research Data Management Policy (NSERC).

6Data retention and destruction

Data typeDestruction
Pseudonym ↔ identity linkage tableDecember 2027
URLs, copy-pasted content, web page contentDecember 2028
Anonymised aggregated metricsRetained until no later than December 2035

Destruction is carried out by deleting data from Cosmos DB, purging exports, and destroying Azure Key Vault encryption keys, making recovery technically impossible including from backups.

7Participant rights

Any participant may: access their data, withdraw consent and request data deletion (while the linkage table exists, before December 2027), or ask questions to the principal investigator.
